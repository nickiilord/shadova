# .agents 目录规范

本目录是跨工具 agent 约定目录（Agent Skills 标准），当前承载 skills。仓库规则单一真相源是根目录 `AGENTS.md`，本文件不重复规则，只记录 skills 自身的组织规范。

## 目录结构

```
.agents/
├── README.md          # 本文件：skills 骨架规范（唯一信息）
└── skills/
    └── <skill-name>/
        └── SKILL.md   # 每个 skill 一个目录，文件名必须为 SKILL.md
```

## 双目录同步（强制）

skills 必须同时维护两份，缺一不可：

- `.agents/skills/` — 跨工具标准目录（Cursor / Windsurf / Copilot 等读取）
- `.claude/skills/` — Claude Code 专用（实证：Claude Code 只扫描此目录，`.agents/skills/` 对它对不可见且静默忽略）

新增或修改 skill 时两处同步提交，禁止只更新一边——双目录各自演化就是双源分叉。

## SKILL.md 统一骨架

所有 skill 必须按以下结构编写，防止未来 skill 写法分叉：

1. **frontmatter**：`name` + `description`。description 必须写清触发场景与症状（如"菜单点击 404"），帮助 agent 判断何时加载。
2. **何时使用**：触发条件清单（正面场景 + 故障症状）。
3. **前置假设**：开始前必须确认的信息，避免中途返工。
4. **步骤清单**：每步 = 操作 + 验证命令（可执行，禁止纯散文描述）。
5. **红线**（must-not）：本仓库明令禁止的写法，逐条列出。
6. **范例索引**：指向仓库内真实代表文件（SSOT）。**禁止在 skill 内嵌模板代码**——模板与真实代码必然分叉，一律索引到范例文件。
7. **易错点**：踩过的坑，写成因和规避方式。

## 新增/修改 skill 检查清单

- [ ] 触发场景能写成具体症状吗？（写不出的说明不是独立流程，不值得封装）
- [ ] 每步都有可执行验证命令吗？
- [ ] 是索引范例文件而非复制代码模式吗？
- [ ] 与现有 skill 有内容重复吗？（重复 = 双源；应在编排层 skill 中引用，不复制）
- [ ] 覆盖了至少一个"漏一步就静默出错"的环节吗？（否则是文档不是 skill）
- [ ] **双目录同步了吗？**（`.agents/skills/` 与 `.claude/skills/` 必须同一份内容提交）
